How the numbers are calculated

The default scenario is 50,000 stored chunks and 50,000 queries a month. The calculator assumes each 1,536-dimension chunk takes about 6 KB, so 50,000 chunks are about 0.3 GB, which at Pinecone's $0.33 per GB is about $0.10. It assumes 10 read units per query, so 50,000 queries use 500,000 read units, which at $16 per million is $8, for about $8.10 in usage. The 6 KB per chunk and 10 read units per query are assumptions, and Pinecone read units scale with index size, so real bills differ. We have not measured recall, latency or throughput on any of them. FAQ

[lt_faq] What is a chunk?|A chunk is a piece of a document, such as a few paragraphs, that is converted into a vector and stored so it can be searched. Chunk size affects both answer quality and cost. What drives the cost of a RAG system?|For most workloads the answer model dominates, because every query pays for the retrieved context as input tokens plus the generated answer. Vector storage and queries are usually the smaller line item, unless query volume is very high. Do I need a dedicated vector database?|Not always. Postgres with a vector extension can handle small and medium knowledge bases at a low fixed cost. Move to a dedicated service when your scale, latency needs or operations capacity justify the extra bill. What happens if I change my chunk size?|You usually need to re-embed and re-index your documents, which costs embedding fees and write units. Decide your chunking strategy on a sample before indexing everything. How can I reduce the cost per query?|Retrieve fewer and more relevant chunks, cap context length, use a cheaper model for simple questions, and turn on prompt caching for repeated instructions. Measure answer quality each time you make a change. [/lt_faq]
